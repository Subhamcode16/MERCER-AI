## 1. Constraint-Based Decision Model
Rather than executing static, imperative rules, the Decision Engine functions as a **Multi-Objective Constraint Solver**. During a campaign planning session, each active Intelligence Domain (Product, Brand, Campaign, Platform) writes weighted constraints onto the Blackboard.

```
┌──────────────────────────┐     ┌──────────────────────────┐
│   Product Constraints    │     │    Brand Constraints     │
│ (Level 1: Physical Truth)│     │  (Level 2: Guidelines)   │
└────────────┬─────────────┘     └────────────┬─────────────┘
             │                                │
             └──────────────► ┌───────────┐ ◄─┘
                              │  Central  │
             ┌──────────────► │  Solver   │ ◄─► [Creative Review Engine]
             │                └─────┬─────┘
             │                      │
┌────────────┴─────────────┐        ▼
│   Campaign Objectives    │  ┌───────────┐
│ (Level 3: Probabilities) │  │ Resolved  ├─► [Approved Creative State]
└──────────────────────────┘  │ Campaign  │
                              └───────────┘
```

The Central Solver runs a multi-objective optimization to reconcile these inputs, ensuring that physical material laws are strictly preserved while brand identity guidelines and user intent are balanced.

## 1.1 Compiled Knowledge Pipeline
To ensure strict verification and prevent runtime parsing overhead, the platform uses a two-step knowledge pipeline:
1. **Canonical Source (Markdown):** Domain Blueprints, Knowledge Units, and Decision Rules are authored in Markdown with structured YAML frontmatter for human readability.
2. **Build Compilation:** A build pipeline compiles the Markdown files into validated JSON schemas and runtime artifacts.
3. **Runtime Execution:** Agents and the Constraint Solver consume **only the compiled JSON schemas**, never raw Markdown. This eliminates runtime parsing latency and guarantees schema validity before execution.

## 2. Adaptive Intervention Model
When the Decision Engine resolves constraints or encounters conflicts, it routes adjustments through three tiers of user intervention based on creative impact:

| Intervention Tier | Scope / Impact | Action Protocol |
|---|---|---|
| **Tier 1: Silent Corrections** | Low-impact technical optimizations (e.g. minor color temperature shifts, focal length compression adjustments to prevent distortion). | Applied automatically. Logged silently to the Blackboard's resolution trace. |
| **Tier 2: Interactive Recommendations** | Heuristic creative guidance (e.g. suggesting an alternate lighting angle for suede, recommending temple jewelry for bridal setups). | Flags the UI card. Presents the reasoning to the user with a single-click "Apply" option. |
| **Tier 3: Mandatory Approval** | Changes directly affecting brand strategy, positioning, or business intent (e.g. changing the core campaign intent from Festive to Catalog). | Blocks execution immediately. Renders a prominent approval card in the UI explaining the trade-off. |

---

## 3. Conflict Resolution & Constraint Relaxation
When constraints directly compete (e.g. a user wants a "billowing, lightweight drape" on a heavy "Banarasi Silk Saree"), the Solver arbitrates using a strict priority scale:

1. **Level 1 (Physical Truth):** Non-negotiable physical constraints (e.g. fabric physics, metal reflection behaviors). The solver *never* relaxes Level 1 constraints. If a conflict occurs, it forces a Tier 2/3 intervention.
2. **Level 2 (Expert Heuristics):** Overridable guidelines. The solver can propose relaxing these if it satisfies a stronger Level 1 or User Intent constraint, presenting it as an Interactive Recommendation.
3. **Level 3 (Observed Statistics):** Probabilistic defaults. Relaxed automatically to accommodate explicit user intent.

## 4. Explainability & Constraint Relaxation Compiler
Every compiled campaign state must be accompanied by an **Explanation & Justification Statement** compiled by the Decision Engine:
- **Structure:** The compiler details:
  - Which constraints were successfully satisfied (e.g. color palette alignment).
  - Which constraints were relaxed and the rationale (e.g. relaxing Golden Hour to preserve jewel-tone color saturation).
  - The technical reasoning mapping back to specific Knowledge Units (KUs).
- **Template:**
  ```text
  "We resolved this campaign setup by satisfying 92% of active constraints. We applied [DR-SAREE-001] (Structured Folds) to preserve [KU-SAREE-001] (Banarasi Weight). We relaxed the default Golden Hour lighting to Warm-Neutral Studio to preserve the saturated jewel tone of your brand's silk colors, satisfying [DR-SAREE-006]."
  ```
