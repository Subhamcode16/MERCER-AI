# RES-007: Knowledge Synthesis Engine (Processing Station 7)

## Purpose

The **Knowledge Synthesis Engine** replaces the traditional concept of "Graph Construction."

Standard knowledge graphs connect facts via relationships (Node -> Edge -> Node). The Visual Intelligence Platform requires something deeper: **Situated Knowledge**. The meaning of an entity changes drastically depending on its context (e.g., `Silk` in a `Luxury Wedding` context vs. `Silk` in a `Summer Casual` context).

Processing Station 7 ingests the verified *Knowledge Claims* (from Station 6) and executes a four-stage resolution pipeline to synthesize this data into a context-aware Knowledge Graph. Furthermore, it introduces the concept of **Knowledge Patterns**, the probabilistic rules derived from analyzing thousands of semantic contexts.

---

## 1. The Synthesis Pipeline

When a verified `Knowledge Claim` (e.g., `Subject: Fabric`, `Predicate: Is`, `Value: Silk`, `Evidence: [...]`) arrives at Station 7, it undergoes four distinct resolution stages.

### Stage 1: Claim Resolution
- **Goal:** Deduplication and merging.
- **Action:** If two different models extracted the same claim for the same image (e.g., the Garment Model and the Texture Model both claimed the fabric was silk), those claims are merged. The highest confidence score is retained, and the `Evidence` arrays are concatenated.

### Stage 2: Entity Resolution
- **Goal:** Mapping values to the formal Ontology.
- **Action:** The string value `"Silk"` is mapped to the canonical `VIO-006` entity `URI:fashion:textile:silk`. This guarantees that typos or model variations ("Silky", "Raw Silk") resolve to the exact same node in the graph.

### Stage 3: Relationship Resolution
- **Goal:** Connecting the entity to the specific Image Asset.
- **Action:** A directed edge is created: `(Asset:UUID) -[FEATURES {Confidence: 0.96}]-> (Entity:Silk)`. The edge property stores the `Evidence` and `ProducingModel`, preserving provenance.

### Stage 4: Context Resolution (The Intelligence Layer)
- **Goal:** Grouping entities by their shared semantic environment.
- **Action:** The engine looks at all claims attached to the `Asset:UUID`. It links the `Silk` node with the `Luxury Wedding` node, the `Warm Lighting` node, and the `Zari Border` node, creating a unified **Context Subgraph**.

---

## 2. Knowledge Patterns (The Top Layer)

The most valuable data in the platform is not the facts themselves, but the patterns hidden within them.

While Context Resolution (Stage 4) builds the graph, the true intelligence emerges from analyzing that graph at scale. This introduces a new layer of knowledge: **Knowledge Patterns**.

### What is a Pattern?
A pattern is a statistically significant correlation discovered across thousands of Context Subgraphs. It represents a "rule" of creative direction.

**Example Pattern:**
```yaml
PatternID: "pat-luxury-bridal-001"
Theme: "Luxury Bridal Campaigns"
Correlations:
  - Entity: "Golden Hour Lighting" (Probability: 0.92)
  - Entity: "Antique Gold Jewelry" (Probability: 0.95)
  - Entity: "Warm Color Palette" (Probability: 0.89)
  - Entity: "Palace Architecture" (Probability: 0.81)
```

### How Patterns are Generated
Generating patterns across millions of nodes is computationally expensive. Therefore:
- **Synchronous vs. Asynchronous:** Station 7 does *not* calculate patterns in real-time. It only builds the Graph. 
- **The Pattern Discovery Job:** The actual mathematical extraction of Knowledge Patterns is handled by a heavy, asynchronous Cron Job running nightly on the **Intelligence Improvement Platform (Track C)**. Track C analyzes the graph, calculates the probabilities, and injects the resulting `Knowledge Patterns` back into the graph for retrieval.

---

## 3. The Four Layers of Knowledge

The completion of Station 7 solidifies the four distinct layers of data within the platform:

1. **Observations:** Raw pixels and unverified extractions (Stations 1-5).
2. **Knowledge Claims:** Provenance-backed, verifiable facts (Station 6).
3. **Knowledge Graph:** Situated, context-aware connected nodes (Station 7).
4. **Knowledge Patterns:** Probabilistic creative rules (Generated by Track C).

This hierarchy ensures that the final Runtime Platform retrieves *wisdom* (Patterns), rather than just raw *data* (Observations).
