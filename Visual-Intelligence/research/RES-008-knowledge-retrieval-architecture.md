# RES-008: Knowledge Retrieval Architecture (Processing Station 8)

## Purpose

**Processing Station 8** is the final stage of the Visual Intelligence Factory (VIF). Its purpose is to bridge the asynchronous Knowledge Factory (Track B) with the synchronous Runtime Platform (Track A).

Traditional retrieval-augmented generation (RAG) systems rely almost entirely on Vector search to return a list of text chunks. The Visual Intelligence Platform requires **Hybrid Retrieval**. When a user prompts the Runtime to generate a "Luxury Bridal Campaign," the Retriever cannot just return 100 random bridal images. It must retrieve the *Knowledge Patterns* (the probabilistic rules of luxury bridal), the semantic entities, and the verifiable *Evidence* backing those rules.

---

## 1. The Indexing Engine

Station 8 ingests the finished Knowledge Graph (and the Knowledge Patterns generated by Track C) and builds three parallel indices to support hybrid retrieval:

### A. The Vector Index
- **Purpose:** Semantic similarity search.
- **Content:** Deep embeddings of the Knowledge Claims, Evidence strings, and visual feature vectors.
- **Use Case:** Finding "moods similar to melancholic."

### B. The Graph Index
- **Purpose:** Relational and Contextual search.
- **Content:** The raw nodes, edges, and Context Subgraphs built in Station 7.
- **Use Case:** "Find all Garments that are explicitly linked to both 'Banarasi' and 'Summer'."

### C. The Pattern Index
- **Purpose:** Creative Rule retrieval.
- **Content:** The Pattern Engine maintains two distinct repositories:
  1. **Statistical Pattern Discovery:** Data-driven patterns mined from thousands of claims (e.g., "92% of luxury bridal uses warm lighting").
  2. **Expert Pattern Library:** Human-curated, structured visual rules for specific aesthetics (e.g., "Sabyasachi Editorial Style" -> 85mm lens, f/2.8, warm tones).
- **Use Case:** Returning the architectural blueprint for a "Luxury Bridal" prompt.

---

## 2. The Retrieval Flow (Runtime Integration)

When a user submits a prompt to the Runtime (e.g., "Generate a Luxury Bridal Campaign"), the `ARC-001 Decision Engine` queries the Knowledge Retrieval Architecture.

The flow operates as follows:

1. **Pattern First:** The Retriever queries the **Pattern Index**. It retrieves `Pattern:pat-luxury-bridal-001`.
2. **Rule Extraction:** It extracts the rules: Golden Hour (92%), Antique Gold Jewelry (95%), Warm Palette (89%).
3. **Graph Validation:** It queries the **Graph Index** to find the top 5 reference assets that perfectly embody these specific rules within a single Context Subgraph.
4. **Evidence Retrieval:** It packages the reference assets, their Knowledge Claims, and the *Evidence* strings.

### The Runtime Payload
The Retriever returns a massive, highly structured JSON payload to the Runtime's `Creative Context (ARC-002)`. 

Instead of a basic context window containing "Here are some bridal images," the Runtime receives:
- The statistical rules of the requested aesthetic.
- The reference imagery.
- The semantic logic (Evidence) explaining *why* those images were selected.

---

## 3. Confidence-Aware Retrieval

Because every claim in the Knowledge Graph has a `Confidence` score and `VerificationStatus` (from Station 6), the Retriever executes **Confidence-Aware Retrieval**.

- **Thresholding:** The Retriever can be instructed to only return patterns derived from claims with a confidence > 0.99.
- **Fallback:** If a user requests a highly obscure aesthetic that lacks sufficient high-confidence Knowledge Patterns, the Retriever can gracefully degrade, searching the Vector Index for semantic approximations, rather than hallucinating rules.

## Conclusion

With the completion of Processing Station 8, the Visual Intelligence Factory is finalized. 

Raw pixels have been ingested, assessed, masked, processed through domain and universal models, verified by humans, synthesized into a situated graph, aggregated into patterns, and indexed for instantaneous retrieval. The intelligence is now ready for consumption by the Runtime.
