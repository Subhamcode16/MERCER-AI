## 1. Real-Time State Synchronization Framework
The Bento Canvas workspace coordinates state changes between the browser client and the FastAPI backend using WebSockets.

### 1.1 Connection Architecture
- **Protocol:** WebSocket (Secure: `wss://`)
- **Connection Endpoint:** `/ws/workspace/{workspace_id}/campaign/{campaign_id}`
- **Authentication:** Token-based query param (`?token=JWT_STRING`), verified against Supabase.

### 1.2 Message Protocol Examples
- **Client Modifies Card State:**
  ```json
  {
    "event": "card_update",
    "payload": {
      "card_id": "visual_composition",
      "value": { "lighting": "Golden Hour" }
    }
  }
  ```
- **Server Broadcasts Update:**
  ```json
  {
    "event": "state_broadcast",
    "payload": {
      "active_cards": {
        "visual_composition": { "lighting": "Golden Hour", "owner": "user_id_1" }
      }
    }
  }
  ```

## 2. Server-Side Conflict Resolution Engine
When a client sends a card update, the backend checks for rules violations in real-time.

```
[WebSocket Client Payload]
            │
            ▼
┌───────────────────────────────┐
│     Validate Schema & Rules   │
└───────────┬───────────┬───────┘
            │           │
            │ (Pass)    │ (Fail / Contradict)
            ▼           ▼
┌───────────────┐   ┌───────────────────────────────┐
│ Commit State  │   │ Dispatch WebSocket Event      │
│   to DB &     │   │ "contradiction_alert"         │
│   Broadcast   │   │ - Warning message             │
│               │   │ - Active override options     │
└───────────────┘   └───────────────────────────────┘
```

### 2.1 Rule Check Pipeline
1. Check the payload against `brands.guidelines` and `ontology.rules`.
2. If conflict detected, serialize a `contradiction_alert` event.
3. Broadcast the alert to the editor client without blocking the commit state (allowing user to override).

## 3. Decision Ownership Ledger
To ensure all strategic decisions have auditable provenance, card states include ownership metadata.

### 3.1 Ownership Schema
Every card update is appended to the workspace event stream:
```json
{
  "campaign_id": "ObjectId",
  "card_id": "string",
  "transition": {
    "from_value": "any",
    "to_value": "any"
  },
  "owner": {
    "type": "string", // "ai" | "user" | "system"
    "id": "string" // User ID or AI Agent ID
  },
  "approved_for_rendering": "boolean",
  "timestamp": "datetime"
}
```
If a card is not marked as `approved_for_rendering: true` by the user, the rendering route will reject the generation request.
