# Atelier OS
## Application Flow Architecture

Version: 1.0
Status: LOCKED

---

# Philosophy

Atelier is not a traditional AI application.

It is a Creative Intelligence Operating System.

Every module exists to support one continuous creative thinking process rather than isolated tools.

The application should feel like moving through a creative institution instead of switching between software pages.

---

# Global Architecture

```
Atelier OS

├── Campaign Studio
├── Material Library
├── Atlas
├── Research
├── Knowledge
├── Archive
├── Settings
```

Campaign Studio is the primary workspace.

All other modules support it.

---

# Navigation Philosophy

Navigation is architectural.

Users move between spaces.

Never between pages.

Each module should feel like another room inside the institution.

Navigation should always preserve context.

---

# Error Philosophy

Errors should educate.

Never confuse.

Every failure should explain:

- What happened
- Why it happened
- How to fix it

---

# Loading Philosophy

Loading is progress.

Not waiting.

During AI processing display

- Current reasoning
- Active knowledge retrieval
- Evidence count
- Thinking progress

The application should always feel alive.

---

# Context Persistence

The application always remembers

- Active campaign
- Uploaded materials
- Creative direction
- Conversation history
- AI reasoning
- Workspace state

Switching modules never resets context.

---

# Session End

When the user leaves

The campaign state is automatically saved.

The next session resumes exactly where the user stopped.

No restoration dialog.

No manual recovery.

The workspace simply continues.

# Success Criteria

A user should never feel like they are navigating software.

They should feel like they are moving through a continuous creative institution where every workspace, every AI interaction, and every decision is connected by one persistent thread of creative intelligence.
