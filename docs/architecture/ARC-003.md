## 1. Vector Store Layout (pgvector / MongoDB Atlas Search)
Experiential memory is stored as dense vector embeddings alongside context metadata to enable semantic retrieval.

### 1.1 Vector Node Schema
```json
{
  "_id": "ObjectId",
  "workspace_id": "ObjectId",
  "brand_id": "ObjectId",
  "scope": "string", // User | Brand | Product | Domain
  "embedding": [1536], // 1536-dimensional float vector
  "metadata": {
    "product_category": "string",
    "theme_tags": ["string"],
    "campaign_performance_score": "float",
    "user_action": "string" // e.g., "override_palette", "final_export"
  },
  "strength": "float", // Range [0.0, 1.0]
  "created_at": "datetime",
  "last_reinforced_at": "datetime"
}
```

## 3. Mathematical Decay & Reinforcement Model
Memory strength updates dynamically based on use frequency, recency, and performance metrics.

### 3.1 Memory Strength Equation
Memory strength ($S_t$) at time $t$ is calculated as:

$$S_t = S_0 \cdot e^{-\lambda \cdot \Delta t} + \sum_{i} R_i$$

Where:
- $S_0$ = Initial memory strength (default = `0.5` upon creation).
- $\lambda$ = Half-life decay factor (standard decay: $\lambda = 0.005$ per day).
- $\Delta t$ = Days elapsed since `last_reinforced_at`.
- $R_i$ = Reinforcement increment.

### 3.2 Reinforcement Value Table ($R_i$)

| Event Trigger | Reinforcement Value ($R_i$) | Impact |
|---|---|---|
| User accepts AI proposal | $+0.2$ | Strengthens memory nodes |
| User edits proposal card | $+0.1$ | Shifts memory coordinates |
| User explicitly pins card | $+1.0$ (locks decay to $0.0$) | Permanent Brand DNA |
| Campaign exceeds CTR target | $+0.3$ | Positive reinforcement |
| User deletes/rejects output | $-0.4$ | Direct weakening |
