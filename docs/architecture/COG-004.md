## 1. Dynamic Task Decomposition Framework
When a campaign objective is created, the Planning Engine breaks it down into a Directed Acyclic Graph (DAG) of executable sub-tasks, establishing dependencies, resource costs, and completion targets.

```

       │   Ingest & Analyze     │ (Task 1: Silhouette / Color extraction)
       └───────────┬────────────┘
                   │
                   ▼
       ┌────────────────────────┐
       │   Strategy Synthesis   │ (Task 2: Compile Bento Cards & proposals)
       └───────────┬────────────┘
                   │
                   ▼
       ┌────────────────────────┐
       │   Collaborative Pause  │ (Task 3: Gated User Review & Override)
       └───────────┬────────────┘
```

## 2. Structured Campaign Task Schemas
Every task in the campaign graph conforms to a standard schema:
```json
{
  "task_id": "string",
  "dependencies": ["string"],
  "status": "string", // "pending" | "running" | "completed" | "failed"
  "cost_estimate": "integer", // credit cost
  "execution_mode": "string" // "automated" | "collaborative_gate"
}
```

---

## 3. Dependency Resolution & Path Scheduling
The Planning Engine schedules task execution based on three execution policies:

### 3.1 Gated Blocking
- Tasks marked with `execution_mode: "collaborative_gate"` (e.g. Strategy Review) halt all downstream tasks. Execution cannot proceed past a gate without manual user approval.

### 3.2 Parallel Job Dispatch
- Once the gate is cleared, independent rendering tasks (e.g., rendering different product variants or channel formats) are dispatched concurrently.
- The system manages outbound API limits using a concurrent semaphore to prevent provider rate limits.

### 3.3 Dynamic Path Recalculation
- If a rendering task fails, the Planning Engine recalculates the remaining path.
- The failed node is flagged, its credits are refunded, but sibling render tasks continue processing unaffected to maximize pipeline output.
